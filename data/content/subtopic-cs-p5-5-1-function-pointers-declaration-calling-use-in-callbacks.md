## What it is
A function pointer is a variable that stores the memory address of a function. Just as a `double*` stores the address of a `double` in memory, a function pointer stores the starting address of a block of executable code (a function) in memory. This allows you to treat functions as data: you can pass them to other functions, store them in arrays, and call them indirectly through the pointer.

## Why it matters
Function pointers are the C mechanism for implementing "higher-order functions" and callbacks, which are fundamental to modern software.
- In **physics and scientific computing**, numerical solvers for differential equations (e.g., Runge-Kutta methods) take a function pointer to the derivative they need to integrate. This decouples the generic solver algorithm from the specific physics problem you're solving.
- In **systems programming**, they are used for callback mechanisms in event-driven systems (like GUIs or network servers) and for implementing generic algorithms like C's standard library `qsort` function.

## How to study it (step by step)
1.  **Find a function's address.** Write a simple function, `int add(int a, int b) { return a + b; }`. In `main`, print its address: `printf("Address of add: %p\n", add);`. Observe that the function name itself, like an array name, evaluates to its starting address.
2.  **Master the declaration syntax.** The syntax is the hardest part. The rule is: declare the pointer as if you were declaring a function, but replace the function's name `f` with `(*pf)`. So, a function `int f(int, int)` has a corresponding pointer `int (*pf)(int, int)`. Use an online tool like `cdecl` to practice translating between C declarations and English.
3.  **Assign and call.** Declare a pointer `pf` as above. Assign the `add` function to it: `pf = add;` (the `&` is optional but good practice: `pf = &add;`). Call the function through the pointer. Both syntaxes work and are equivalent: `int result = (*pf)(3, 4);` and `int result = pf(3, 4);`. Understand that the second is just syntactic sugar.
4.  **Write a "worker" function.** Write a function `int compute(int a, int b, int (*op)(int, int))`. This function takes two integers and a function pointer `op`. Inside `compute`, call the passed-in function: `return op(a, b);`.
5.  **Use your worker function.** In `main`, call `compute` twice. First, pass it your `add` function: `compute(10, 5, add)`. Then, write a `subtract` function and pass that instead: `compute(10, 5, subtract)`. This demonstrates the core power: changing behavior at runtime by passing different functions as arguments.
6.  **Implement a simple callback.** Write a function `perform_long_task(void (*callback)(int))`. Inside, simulate work (e.g., a loop), and when done, call the provided function: `callback(100);` to signal "100% complete". In `main`, define a function `void on_complete(int status) { ... }` and pass it to `perform_long_task`. This inverts the flow of control: the library function calls *your* code.

## Key ideas, with intuition
1.  **Code is Data.** The machine code generated by the compiler for your functions resides in a specific section of memory (the "text segment"). A function pointer is simply the address of the first instruction of a given function. It's no more magical than a pointer to an `int`.

2.  **The Signature is the Type.** The compiler needs to know what kind of function a pointer points to, so it can verify that you're passing the correct number and types of arguments and using the return value correctly. The "type" of a function pointer is therefore its full signature.
    $$
    \text{Function: } \quad \texttt{double f(int x, char* y);} \\
    \text{Pointer Type: } \quad \texttt{double (*)(int, char*);}
    $$

3.  **Declaration Mimics Use.** The declaration syntax `return_type (*pointer_name)(params)` looks complex, but it's logical. The parentheses `(*pointer_name)` are crucial. They bind the `*` to the name, signifying it's a pointer. The rest of the declaration, `return_type ... (params)`, specifies what it points *to*: a function that returns `return_type` and takes `params`. Without the parentheses, `return_type *pointer_name(params)` would declare a function named `pointer_name` that returns a pointer of `return_type*`.

4.  **Callbacks Invert Control.** Normally, your `main` function calls library functions. With a callback, you give a library function a pointer to one of *your* functions. The library function does its work and then calls your function back. You don't call it; it calls you. This is essential for handling asynchronous events like "a network packet has arrived" or "the user clicked a button".

## Worked example
We will implement a generic `map` function that applies an operation to every element of an integer array. This is a classic use case for function pointers, allowing the `map` logic to be separated from the specific operation.

```c
#include <stdio.h>
#include <stdlib.h>

// Operation 1: Square a number
int square(int x) {
    return x * x;
}

// Operation 2: Double a number
int doubler(int x) {
    return x * 2;
}

// Generic 'map' function that takes a function pointer
// The pointer 'op' must point to a function that takes an int and returns an int.
void map(int *arr, size_t n, int (*op)(int)) {
    // Step 1: Check for valid inputs.
    if (!arr || !op) {
        return;
    }

    // Step 2: Iterate through the array.
    for (size_t i = 0; i < n; i++) {
        // Step 3: Apply the function pointed to by 'op' to the current element.
        // The result of the function call overwrites the original value.
        arr[i] = op(arr[i]);
    }
}

void print_array(int *arr, size_t n) {
    for (size_t i = 0; i < n; i++) {
        printf("%d ", arr[i]);
    }
    printf("\n");
}

int main(void) {
    int my_array[] = {1, 2, 3, 4, 5};
    size_t n = sizeof(my_array) / sizeof(my_array[0]);

    printf("Original array: ");
    print_array(my_array, n);

    // Step 4: Call map, passing the 'square' function as the operation.
    map(my_array, n, square);
    printf("After squaring: ");
    print_array(my_array, n);

    // Reset array for the next example
    int my_array2[] = {1, 2, 3, 4, 5};

    // Step 5: Call map again, this time passing the 'doubler' function.
    map(my_array2, n, doubler);
    printf("After doubling: ");
    print_array(my_array2, n);

    return 0;
}
```

### Reflection
-   **Step 1-3:** The `map` function is completely generic. It knows how to iterate over an array, but it has no knowledge of *what* to do to each element. It relies on its `op` parameter.
-   **Step 4:** We inject the "squaring" behavior into the generic `map` algorithm by passing the address of the `square` function. `map` then calls `square` for each element.
-   **Step 5:** We reuse the exact same `map` function but provide a different behavior, "doubling," by passing the address of the `doubler` function. This demonstrates the power of decoupling the algorithm from the specific operation.

## Memory technique — remember this forever
1.  **The Subcontractor Analogy:** Think of a function pointer as a **subcontractor's phone number**. Your `main` function is the general contractor building a house. For the electrical work, you don't hard-code "Call Bob's Electric". Instead, you have a line in your project plan: `electrical_contact`. You can pencil in Bob's number. If Bob is busy, you can erase it and write in Alice's number. The plan (`map` function) stays the same—it just says "call the electrician at this number". The specific electrician (`square` or `doubler` function) can be changed at any time. A **callback** is when the electrician calls you back to say the wiring is done.

2.  **Must-Overlearn Syntax:** Burn these three patterns into your memory.
    -   **Declaration:** `return_type (*pointer_name)(param_type1, ...);`
    -   **Assignment:** `pointer_name = function_name;`
    -   **Invocation:** `return_value = pointer_name(arg1, ...);`

3.  **Spaced Repetition Schedule:** Re-derive and rewrite the `map` example from scratch on this schedule:

    -   In 3 days.
    -   In 7 days.
    -   In 16 days.

4.  **First Principles Derivation:** If you forget the declaration syntax, rebuild it.
    -   Start with a normal function declaration: `int f(int a);`
    -   You want a pointer, so you need a `*`. Where does it go?
    -   It must be tied to the name, not the return type. `int* f(int a);` is a function returning a pointer. That's wrong.
    -   So, the `*` must be next to the name: `*f`.
    -   But `int *f(int a);` has the `*` binding to the `int`. Use parentheses to force the `*` to bind to `f` first: `(*f)`.
    -   Substitute `(*f)` back into the original declaration: `int (*f)(int a);`. This is the correct syntax.

## Common mistakes
1.  **Incorrect Declaration:** `int* fptr(int);` This declares a function named `fptr` that takes an `int` and returns a pointer to an `int`. You almost always want `int (*fptr)(int);`, which declares a pointer `fptr` to a function. The parentheses are not optional.
2.  **Signature Mismatch:** Trying to assign a function to a pointer with a different signature. For example, `double (*fptr)(double); fptr = square;` where `square` is `int square(int)`. The compiler will throw an error because the parameter and return types do not match.
3.  **Calling a NULL Pointer:** Just like any other pointer, if a function pointer is `NULL` or uninitialized, trying to call it will result in a segmentation fault or undefined behavior. Always check if a function pointer received as a parameter is non-NULL before calling it.
