## 1. What it is — in plain English

Imagine you have a very long book, and you want to quickly find all occurrences of a particular phrase, or maybe even just see how often different phrases appear. If the book didn't have an index, you'd have to read through it page by page, which would take ages.

A **Suffix Array** is like a super-smart index for a string (which you can think of as a very long word or a sequence of characters). Instead of indexing words, it indexes *all possible endings* of the string. We call these endings "suffixes." For example, if your string is "banana", its endings are "banana", "anana", "nana", "ana", "na", "a".

What the Suffix Array does is take all these endings, sort them alphabetically (lexicographically), and then tell you *where each sorted ending originally started* in the main string. So, for "banana", it would tell you that "a" starts at position 5, "ana" starts at position 3, "anana" starts at position 1, and so on, all in alphabetical order. It doesn't store the suffixes themselves, just their starting positions.

The **LCP Array** (Longest Common Prefix Array) works hand-in-hand with the Suffix Array. Once you have your sorted list of suffixes (via their starting positions from the Suffix Array), the LCP Array tells you, for each pair of *adjacent* suffixes in that sorted list, how many characters they share at the very beginning. For "banana", if "ana" comes right before "anana" in the sorted list, the LCP Array would tell you they share "ana" (3 characters) as their longest common prefix. It's like knowing how similar neighboring entries in your sorted index are.

## 2. Why it matters — real-world applications

Suffix Arrays and LCP Arrays are fundamental tools in computer science, especially in areas dealing with large amounts of text or sequence data. Their efficiency in finding patterns makes them invaluable.

1.  **Bioinformatics and Genomics**:
    *   **Application**: DNA sequence alignment, finding genetic markers, identifying common evolutionary patterns.
    *   **Specificity**: Companies like Illumina or Pacific Biosciences use algorithms that might leverage suffix array-like structures to quickly map short DNA reads (sequences generated by sequencing machines) back to a large reference genome. For instance, finding all occurrences of a specific gene sequence within a human genome (billions of characters) is a classic problem solved efficiently with suffix arrays. This is crucial for understanding disease susceptibility or evolutionary relationships.
    *   **Connection to ML**: Machine learning models for genomic analysis often rely on highly optimized data structures to preprocess and query sequence data, where suffix arrays can serve as a powerful indexing mechanism for feature extraction (e.g., identifying k-mers or repetitive elements).

2.  **Text Search and Information Retrieval**:
    *   **Application**: Fast full-text search in large documents or databases, like the `grep` utility on Linux, or search engines indexing vast amounts of web pages.
    *   **Specificity**: Imagine Google's backend, needing to find every page containing a specific phrase. While Google uses more complex, distributed indices, the core idea of quickly locating patterns within massive text corpora is exactly what suffix arrays excel at. They allow for finding all occurrences of a pattern $P$ in a text $T$ in $O(|P| + \text{occurrences})$ time, after the initial $O(|T| \log |T|)$ construction.

3.  **Data Compression**:
    *   **Application**: Algorithms like the Burrows-Wheeler Transform (BWT), which is a key component of popular compression tools like bzip2.
    *   **Specificity**: The BWT reorders a block of text into a form that is more easily compressible by subsequent algorithms (like move-to-front coding and run-length encoding). The core step of BWT involves sorting all cyclic shifts of a string, which is essentially a specialized form of suffix array construction. The output of BWT is directly related to the suffix array of the string.

4.  **Plagiarism Detection and Code Similarity**:
    *   **Application**: Identifying duplicate content in academic papers, legal documents, or source code.
    *   **Specificity**: Services like Turnitin or tools used by software companies to check for code reuse can employ suffix arrays. By building suffix arrays (or generalized suffix arrays for multiple documents) and LCP arrays for documents, one can efficiently find long common substrings between texts, indicating potential plagiarism or copied code. This is particularly relevant in fields like aerospace engineering, where rigorous code verification and intellectual property protection are paramount.

## 4. The core idea — step by step

The core idea behind constructing a Suffix Array efficiently (in $O(N \log N)$ time) is to avoid the naive $O(N^2 \log N)$ approach of sorting $N$ suffixes, each potentially of length $N$, using a standard comparison sort. Instead, we use a clever "doubling" strategy.

Let's use the string $S = \text{"banana"}$ as our running example. We'll append a unique sentinel character, say `$` (which is lexicographically smaller than any other character), to ensure all suffixes are distinct and to handle boundary conditions gracefully. So, $S = \text{"banana\$"}$, with length $N=7$. The indices are $0, 1, ..., 6$.

### Step 1: Define Suffixes and Lexicographical Order

*   **Plain English**: A suffix is just a part of the string starting from some position and going all the way to the end. When we sort them alphabetically, we compare them character by character from left to right.
*   **Example**: For $S = \text{"banana\$"}$:
    *   Suffix at index 0: "banana\$"
    *   Suffix at index 1: "anana\$"
    *   Suffix at index 2: "nana\$"
    *   Suffix at index 3: "ana\$"
    *   Suffix at index 4: "na\$"
    *   Suffix at index 5: "a\$"
    *   Suffix at index 6: "\$"
    Sorted lexicographically, these would be:
    1.  "a\$" (starts at index 5)
    2.  "ana\$" (starts at index 3)
    3.  "anana\$" (starts at index 1)
    4.  "banana\$" (starts at index 0)
    5.  "na\$" (starts at index 4)
    6.  "nana\$" (starts at index 2)
    7.  "\$" (starts at index 6)
*   **Formal Version**: Given a string $S$ of length $N$, a suffix $S_i$ is the substring $S[i \dots N-1]$. Lexicographical comparison $S_i < S_j$ holds if $S[i \dots k] = S[j \dots k]$ for some $k \ge i, j$ and $S[k+1] < S[j+1]$, or if $S_i$ is a prefix of $S_j$.
    The Suffix Array, $SA$, is an array of length $N$ such that $S_{SA[k]} < S_{SA[k+1]}$ for all $0 \le k < N-1$.
*   **What could go wrong**: Forgetting the sentinel character `$` can lead to issues with comparing suffixes of different lengths (e.g., "a" vs "apple") or incorrect sorting if suffixes are prefixes of others. The `$` ensures distinctness and consistent comparison.

### Step 2: Naive Suffix Array Construction (and why it's bad)

*   **Plain English**: The simplest way to build a Suffix Array is to generate all suffixes, put them in a list, and then sort that list using a standard sorting algorithm like Merge Sort.
*   **Example**: For $S = \text{"banana\$"}$:
    Create a list of pairs: `(suffix_string, starting_index)`
    `[("banana$", 0), ("anana$", 1), ("nana$", 2), ("ana$", 3), ("na$", 4), ("a$", 5), ("$", 6)]`
    Then sort this list based on the `suffix_string`.
*   **Formal Version**:
    1.  Create an array of pairs, $P = [(S[i \dots N-1], i) \mid 0 \le i < N]$.
    2.  Sort $P$ lexicographically based on the first element of each pair.
    3.  The Suffix Array $SA$ will then be the array of second elements (indices) from the sorted pairs.
    The time complexity of comparing two suffixes of length up to $N$ is $O(N)$. If we have $N$ suffixes and use a comparison sort ($O(N \log N)$ comparisons), the total time complexity would be $O(N^2 \log N)$.
*   **What could go wrong**: This approach is too slow for large strings ($N=10^5$ or $10^6$). $N^2 \log N$ operations would take hours or days. We need a faster way to compare suffixes.

### Step 3: The Doubling Strategy (The Key for O(N log N))

*   **Plain English**: Instead of comparing entire suffixes directly, which can be long, we'll compare them based on short "chunks" of characters. We start by comparing them based on their first character. Then, we use the results of that comparison to help us compare them based on their first *two* characters. Then four, then eight, and so on, doubling the comparison length in each step. This way, we reuse previous work and avoid re-comparing long strings.
*   **Example**: For $S = \text{"banana\$"}$, we'll use a `rank` array (`pos`) to store the "rank" (lexicographical order) of each suffix based on its first `k` characters.
    *   **Initial step (k=1)**: Sort based on the first character.
        Suffixes:
        `$` (index 6) -> rank 0
        `a` (index 5) -> rank 1
        `a` (index 3) -> rank 1
        `a` (index 1) -> rank 1
        `b` (index 0) -> rank 2
        `n` (index 4) -> rank 3
        `n` (index 2) -> rank 3
        Notice how `a`s and `n`s get the same rank if their first character is the same.
*   **Formal Version**: The doubling strategy, often called the Manber-Myers algorithm or a related suffix array construction algorithm, works in $\log N$ phases. In each phase $k$ (where $k$ takes values $1, 2, 4, \dots, N/2$), we sort suffixes based on their first $k$ characters.
    Instead of sorting actual characters, we use "ranks."
    Let $P_i[k]$ be the lexicographical rank of the suffix starting at index $i$ considering only its first $k$ characters.
    Initially, for $k=1$, $P_i[1]$ is simply the character $S[i]$ itself (or its integer ASCII value). We sort these characters and assign ranks.
    In phase $m$ (where we are considering length $2^{m-1}$), we want to sort suffixes based on length $2^m$. We do this by considering each suffix $S_i$ as a pair: $(P_i[2^{m-1}], P_{i+2^{m-1}}[2^{m-1}])$. That is, we sort based on the rank of its first half and the rank of its second half (which starts $2^{m-1}$ characters later).
    This sorting of pairs can be done efficiently using a stable sorting algorithm like Radix Sort in $O(N)$ time per phase. Since there are $\log N$ phases, the total time complexity is $O(N \log N)$.
*   **What could go wrong**: Using a general comparison sort for pairs in each phase would lead to $O(N \log N)$ per phase, resulting in $O(N \log^2 N)$ total. We need an $O(N)$ stable sort (like Radix Sort) to achieve $O(N \log N)$. Also, handling indices $i+k$ that go beyond $N-1$ requires careful padding or sentinel values; the `$` helps here.

### Step 4: Refined Doubling Algorithm (Manber-Myers variant)

Let's make this concrete. We need two arrays:
*   `SA`: The Suffix Array, storing starting indices of sorted suffixes.
*   `rank`: An array where `rank[i]` stores the lexicographical rank of the suffix starting at index `i`. This is the inverse of `SA`, i.e., `SA[rank[i]] = i`.

**Algorithm Steps:**

1.  **Initialize (k=1, length 1 characters)**:
    *   Create pairs `(S[i], i)` for all `i` from $0$ to $N-1$.
    *   Sort these pairs based on `S[i]`.
    *   Populate `SA`: `SA[j]` is the original index of the $j$-th smallest suffix.
    *   Populate `rank`: Iterate through `SA`. If `S[SA[j]] == S[SA[j-1]]`, then `rank[SA[j]] = rank[SA[j-1]]`. Otherwise, `rank[SA[j]] = rank[SA[j-1]] + 1`. This assigns ranks to suffixes based on their first character.
    *   Example: $S = \text{"banana\$"}$, $N=7$
        Initial pairs: `(b,0), (a,1), (n,2), (a,3), (n,4), (a,5), ($,6)`
        Sorted pairs: `($,6), (a,1), (a,3), (a,5), (b,0), (n,2), (n,4)`
        `SA`: `[6, 5, 3, 1, 0, 4, 2]` (indices of sorted suffixes)
        `rank`:
        `rank[6] = 0` (`$`)
        `rank[5] = 1` (`a`)
        `rank[3] = 1` (`a`)
        `rank[1] = 1` (`a`)
        `rank[0] = 2` (`b`)
        `rank[4] = 3` (`n`)
        `rank[2] = 3` (`n`)
        So, `rank` array: `[2, 1, 3, 1, 3, 1, 0]`

2.  **Iterative Doubling (k=2, 4, 8, ..., until k >= N)**:
    *   In each iteration, we consider suffixes based on blocks of length `k`. We use the `rank` array computed from the *previous* iteration (for length `k/2`).
    *   We want to sort suffixes $S_i$ based on the pair `(rank[i], rank[i+k/2])`. The `rank[i+k/2]` term refers to the rank of the suffix starting `k/2` positions after `i`, effectively giving us the "second half" of the $k$-length block. If `i+k/2` is out of bounds, we treat `rank[i+k/2]` as a special minimum rank (e.g., -1 or 0, depending on implementation, often 0 if ranks start from 1).
    *   Create an array of "items to sort": `[(rank[i], rank[i+k/2], i)]` for all `i`.
    *   Sort these items. This can be done efficiently using Radix Sort (specifically, counting sort for the second component, then counting sort for the first component, which gives a stable sort for pairs).
    *   Update `SA` based on the sorted items.
    *   Update `rank`: Assign new ranks based on the sorted `SA`. If `(rank[SA[j]], rank[SA[j]+k/2]) == (rank[SA[j-1]], rank[SA[j-1]+k/2])`, then `rank[SA[j]] = rank[SA[j-1]]`. Else, `rank[SA[j]] = rank[SA[j-1]] + 1`.
    *   Increment `k = k * 2`.
    *   Repeat until all ranks are unique (i.e., `rank[SA[N-1]] == N-1`).

*   **Formal Version**:
    Let `current_rank` be the `rank` array from the previous phase (length `len`).
    Let `new_SA` and `new_rank` be temporary arrays.
    For `len = 1, 2, 4, ..., < N`:
        1.  Create `items_to_sort` array. For each `i` from $0$ to $N-1$:
            `items_to_sort[i] = (current_rank[i], (i + len < N ? current_rank[i + len] : -1), i)`
            (The `-1` serves as a sentinel rank for out-of-bounds second halves, ensuring they are lexicographically smallest).
        2.  Sort `items_to_sort` using a stable sort based on the pairs `(first_component, second_component)`. This sorting effectively sorts the suffixes.
        3.  Populate `new_SA` from the third component (original index `i`) of the sorted `items_to_sort`.
        4.  Populate `new_rank`:
            `new_rank[new_SA[0]] = 0`
            For `j` from $1$ to $N-1$:
                If `items_to_sort[j].first == items_to_sort[j-1].first` AND `items_to_sort[j].second == items_to_sort[j-1].second`:
                    `new_rank[new_SA[j]] = new_rank[new_SA[j-1]]`
                Else:
                    `new_rank[new_SA[j]] = new_rank[new_SA[j-1]] + 1`
        5.  `SA = new_SA`
        6.  `current_rank = new_rank`
        7.  If `current_rank[SA[N-1]] == N-1`, all suffixes are uniquely ranked, so break.
*   **What could go wrong**: Incorrectly handling the `i+len` out-of-bounds condition. Not using a *stable* sort for the pairs can lead to incorrect results in subsequent iterations. Radix Sort is key for the $O(N)$ per phase.

### Step 5: Constructing the LCP Array (Kasai's Algorithm)

*   **Plain English**: Once we have the Suffix Array `SA` (the sorted list of suffix starting positions), the LCP Array tells us how many characters the $i$-th suffix in `SA` shares with the $(i+1)$-th suffix in `SA`. Kasai's algorithm is a clever way to compute this in linear time, $O(N)$, *after* the Suffix Array is built. It works by observing a relationship between the LCP values of adjacent suffixes.
*   **Example**: For `SA = [6, 5, 3, 1, 0, 4, 2]` for "banana\$":
    Suffixes:
    `SA[0] = 6`: `$`
    `SA[1] = 5`: `a$`
    `SA[2] = 3`: `ana$`
    `SA[3] = 1`: `anana$`
    `SA[4] = 0`: `banana$`
    `SA[5] = 4`: `na$`
    `SA[6] = 2`: `nana$`

    LCP values:
    `LCP[0]` is usually undefined or 0.
    `LCP[1]` = LCP("`$`", "`a$`") = 0
    `LCP[2]` = LCP("`a$`", "`ana$`") = 1 ("a")
    `LCP[3]` = LCP("`ana$`", "`anana$`") = 3 ("ana")
    `LCP[4]` = LCP("`anana$`", "`banana$`") = 0
    `LCP[5]` = LCP("`banana$`", "`na$`") = 0
    `LCP[6]` = LCP("`na$`", "`nana$`") = 2 ("na")

    So, `LCP = [0, 0, 1, 3, 0, 0, 2]` (conventionally `LCP[0]` is often 0 or not used, so the array might be 1-indexed or start from `LCP[1]`).

*   **Formal Version**: Kasai's algorithm (and its variants) computes the LCP array in $O(N)$ time.
    1.  First, compute the `rank` array (also known as `pos` or `inverse_SA`), which is the inverse of `SA`. `rank[i]` stores the position of suffix $S_i$ in the sorted `SA`. That is, `SA[rank[i]] = i`.
    2.  Initialize `LCP` array of size $N$.
    3.  Iterate `i` from $0$ to $N-1$ (for each suffix $S_i$ in its original order).
        Let `k = rank[i]`. This is the position of $S_i$ in the `SA`.
        If `k == 0`, then $S_i$ is the first suffix in `SA`, so `LCP[k]` is 0 (or undefined). Skip.
        Let `j = SA[k-1]`. This is the suffix that comes *just before* $S_i$ in the sorted suffix array.
        We know `LCP[k]` is the length of the longest common prefix between $S_i$ and $S_j$.
        Crucially, Kasai's algorithm uses a property:
        $$LCP(S_i, S_j) \ge LCP(S_{i-1}, S_{j'}) - 1$$
        where $S_j$ is the suffix preceding $S_i$ in `SA`, and $S_{j'}$ is the suffix preceding $S_{i-1}$ in `SA`.
        Let `h` be the LCP length of the previous suffix `S[i-1]` with its predecessor in `SA`.
        We can calculate `LCP[k]` by starting to compare $S_i$ and $S_j$ from character `h-1` (or `h` if `h` was 0), and extending the match.
        Specifically, maintain a variable `h` (height) which is the length of the LCP between $S_i$ and its predecessor in `SA`.
        For `i = 0` to `N-1`:
            If `rank[i] == N-1` (last suffix in SA), then `h = 0` and continue.
            `j = SA[rank[i] + 1]` (the suffix after $S_i$ in `SA`)
            While `i + h < N` and `j + h < N` and `S[i+h] == S[j+h]`:
                `h++`
            `LCP[rank[i]] = h`
            If `h > 0`, then `h--` (for the next iteration, because $S_{i+1}$ and its predecessor $S_{j'}$ will have at least `h-1` common prefix).
    The `LCP` array is usually defined for `LCP[k]` as the LCP between `SA[k]` and `SA[k+1]`. So, the loop above computes `LCP[rank[i]]` which is `LCP(S_i, SA[rank[i]+1])`.
*   **What could go wrong**: Off-by-one errors with `h` and array indices. Misunderstanding the `rank` array (inverse SA) is critical for Kasai's algorithm. The `h--` step is vital for $O(N)$ complexity.

## 5. Worked examples — multiple, with every step shown

Let's work through examples using the doubling algorithm for Suffix Array construction and Kasai's algorithm for LCP Array. We'll use a sentinel character `$` which is lexicographically smaller than any other character.

### Example 1: String "banana"

**Problem**: Construct the Suffix Array and LCP Array for the string $S = \text{"banana"}$.

**Given**: String $S = \text{"banana"}$.
**Want**: Suffix Array $SA$ and LCP Array $LCP$.

We append a sentinel character `$` to $S$, so $S = \text{"banana\$"}$. Its length is $N=7$.
Indices: `0 1 2 3 4 5 6`
Characters: `b a n a n a $`

---

**Part 1: Suffix Array Construction (Doubling Algorithm)**

**Initialization (k=1, length 1 characters)**

1.  **Create initial pairs (character, original_index)**:
    $(S[0], 0) = (\text{'b'}, 0)$
    $(S[1], 1) = (\text{'a'}, 1)$
    $(S[2], 2) = (\text{'n'}, 2)$
    $(S[3], 3) = (\text{'a'}, 3)$
    $(S[4], 4) = (\text{'n'}, 4)$
    $(S[5], 5) = (\text{'a'}, 5)$
    $(S[6], 6) = (\text{'\$'}, 6)$

2.  **Sort these pairs lexicographically by character**:
    $(\text{'\$'}, 6)$
    $(\text{'a'}, 1)$
    $(\text{'a'}, 3)$
    $(\text{'a'}, 5)$
    $(\text{'b'}, 0)$
    $(\text{'n'}, 2)$
    $(\text{'n'}, 4)$

    $SA = [6, 5, 1, 3, 0, 2, 4]$
    $rank = [3, 2, 4, 2, 4, 1, 0]$
    (Note: `rank[SA[N-1]] = rank[4] = 4`. Since $4 \ne N-1=6$, we need more iterations.)

**Iteration 2 (k=4, length 4 characters)**

We sort suffixes based on pairs `(rank[i], rank[i+k/2=2])`.
`rank[i+2]` is 0 if `i+2 >= N`.

1.  **Create pairs `(rank[i], rank[i+2], original_index)`**:
    `i=0`: `(rank[0], rank[2], 0) = (3, 4, 0)`
    `i=1`: `(rank[1], rank[3], 1) = (2, 2, 1)`
    `i=2`: `(rank[2], rank[4], 2) = (4, 4, 2)`
    `i=3`: `(rank[3], rank[5], 3) = (2, 1, 3)`
    `i=4`: `(rank[4], rank[6], 4) = (4, 0, 4)`
    `i=5`: `(rank[5], rank[7], 5) = (1, 0, 5)` (since `rank[7]` is out of bounds, treat as 0)
    `i=6`: `(rank[6], rank[8], 6) = (0, 0, 6)` (since `rank[8]` is out of bounds, treat as 0)

2.  **Sort these pairs**:
    `(0, 0, 6)`
    `(1, 0, 5)`
    `(2, 1, 3)`
    `(2, 2, 1)`
    `(3, 4, 0)`
    `(4, 0, 4)`
    `(4, 4, 2)`

3.  **Update `SA` and `rank`**:
    | Sorted Pair `(rank[i], rank[i+2])` | Original Index | `SA` (current) | `rank` (current) | Explanation                                                                                                 |
    | :---------------------------------- | :------------- | :------------- | :--------------- | :---------------------------------------------------------------------------------------------------------- |
    | `(0, 0)`                            | 6              | `SA[0] = 6`    | `rank[6] = 0`    | `$`                                                                                                         |
    | `(1, 0)`                            | 5              | `SA[1] = 5`    | `rank[5] = 1`    | `a$`                                                                                                        |
    | `(2, 1)`                            | 3              | `SA[2] = 3`    | `rank[3] = 2`    | `ana$`                                                                                                      |
    | `(2, 2)`                            | 1              | `SA[3] = 1`    | `rank[1] = 3`    | `anana$`                                                                                                    |
    | `(3, 4)`                            | 0              | `SA[4] = 0`    | `rank[0] = 4`    | `banana$`                                                                                                   |
    | `(4, 0)`                            | 4              | `SA[5] = 4`    | `rank[4] = 5`    | `na$`                                                                                                       |
    | `(4, 4)`                            | 2              | `SA[6] = 2`    | `rank[2] = 6`    | `nana$`                                                                                                     |

    So, after `k=4` phase:
    $SA = [6, 5, 3, 1, 0, 4, 2]$
    $rank = [4, 3, 6, 2, 5, 1, 0]$
    (Note: `rank[SA[N-1]] = rank[2] = 6`. Since $6 = N-1=6$, all suffixes are uniquely ranked. We are done.)

**Final Suffix Array for "banana\$"**:
$\boxed{SA = [6, 5, 3, 1, 0, 4, 2]}$

**Part 2: LCP Array Construction (Kasai's Algorithm)**

**Given**: $S = \text{"banana\$"}$, $N=7$
$SA = [6, 5, 3, 1, 0, 4, 2]$

1.  **Construct `rank` array (inverse of `SA`)**:
    `rank[i]` = position of suffix $S_i$ in $SA$.
    `SA[0] = 6 \implies rank[6] = 0`
    `SA[1] = 5 \implies rank[5] = 1`
    `SA[2] = 3 \implies rank[3] = 2`
    `SA[3] = 1 \implies rank[1] = 3`
    `SA[4] = 0 \implies rank[0] = 4`
    `SA[5] = 4 \implies rank[4] = 5`
    `SA[6] = 2 \implies rank[2] = 6`
    So, $rank = [4, 3, 6, 2, 5, 1, 0]$

2.  **Compute `LCP` array**:
    Initialize `LCP` array of size $N$ with zeros. `h = 0`.
    Iterate `i` from $0$ to $N-1$:

    *   `i = 0` (`S_0 = "banana$"`)
        `k = rank[0] = 4`.
        If `k == N-1` (which is `6`), `h` becomes 0. Here `k=4 \ne 6`.
        `j = SA[k+1] = SA[4+1] = SA[5] = 4`. (Suffix $S_4 = \text{"na\$"}$)
        Compare $S_0$ (`"banana$"`) and $S_4$ (`"na\$"`).
        `h=0`: `S[0+0] = 'b'`, `S[4+0] = 'n'`. They are different.
        `LCP[k] = LCP[4] = 0`.
        `h` remains 0.

    *   `i = 1` (`S_1 = "anana$"`)
        `k = rank[1] = 3`.
        `j = SA[k+1] = SA[3+1] = SA[4] = 0`. (Suffix $S_0 = \text{"banana\$"}$)
        Compare $S_1$ (`"anana$"`) and $S_0$ (`"banana\$"`).
        `h=0`: `S[1+0] = 'a'`, `S[0+0] = 'b'`. They are different.
        `LCP[k] = LCP[3] = 0`.
        `h` remains 0.

    *   `i = 2` (`S_2 = "nana$"`)
        `k = rank[2] = 6`.
        If `k == N-1` (which is `6`), `h` becomes 0. Here `k=6`.
        `LCP[6] = 0`.
        `h` becomes 0.

    *   `i = 3` (`S_3 = "ana$"`)
        `k = rank[3] = 2`.
        `j = SA[k+1] = SA[2+1] = SA[3] = 1`. (Suffix $S_1 = \text{"anana\$"}$)
        Compare $S_3$ (`"ana$"`) and $S_1$ (`"anana\$"`).
        `h=0`: `S[3+0] = 'a'`, `S[1+0] = 'a'`. Match. `h=1`.
        `S[3+1] = 'n'`, `S[1+1] = 'n'`. Match. `h=2`.
        `S[3+2] = 'a'`, `S[1+2] = 'a'`. Match. `h=3`.
        `S[3+3] = '$'`, `S[1+3] = 'n'`. Mismatch.
        `LCP[k] = LCP[2] = 3`.
        `h` becomes `h-1 = 2`.

    *   `i = 4` (`S_4 = "na$"`)
        `k = rank[4] = 5`.
        `j = SA[k+1] = SA[5+1] = SA[6] = 2`. (Suffix $S_2 = \text{"nana\$"}$)
        Compare $S_4$ (`"na$"`) and $S_2$ (`"nana\$"`).
        `h` was 2. Start comparing from `h`:
        `S[4+0] = 'n'`, `S[2+0] = 'n'`. (Matches from `h=0`)
        `S[4+1] = 'a'`, `S[2+1] = 'a'`. (Matches from `h=1`)
        `S[4+2] = '$'`, `S[2+2] = 'n'`. Mismatch.
        `LCP[k] = LCP[5] = 2`.
        `h` becomes `h-1 = 1`.

    *   `i = 5` (`S_5 = "a$"`)
        `k = rank[5] = 1`.
        `j = SA[k+1] = SA[1+1] = SA[2] = 3`. (Suffix $S_3 = \text{"ana\$"}$)
        Compare $S_5$ (`"a$"`) and $S_3$ (`"ana\$"`).
        `h` was 1. Start comparing from `h`:
        `S[5+0] = 'a'`, `S[3+0] = 'a'`. (Matches from `h=0`)
        `S[5+1] = '$'`, `S[3+1] = 'n'`. Mismatch.
        `LCP[k] = LCP[1] = 1`.
        `h` becomes `h-1 = 0`.

    *   `i = 6` (`S_6 = "$"` )
        `k = rank[6] = 0`.
        `j = SA[k+1] = SA[0+1] = SA[1] = 5`. (Suffix $S_5 = \text{"a\$"}$)
        Compare $S_6$ (`"$"`) and $S_5$ (`"a\$"`).
        `h` was 0. Start comparing from `h`:
        `S[6+0] = '$'`, `S[5+0] = 'a'`. Mismatch.
        `LCP[k] = LCP[0] = 0`.
        `h` becomes `h-1 = -1`. (Clamped to 0 for next iteration, effectively)

**Final LCP Array for "banana\$"**:
$\boxed{LCP = [0, 1, 3, 0, 0, 2, 0]}$
(Conventionally, `LCP[k]` is the LCP between `SA[k]` and `SA[k+1]`. So `LCP[0]` is LCP between `SA[0]` and `SA[1]`, etc. The calculation above is for `LCP[rank[i]]`, which means `LCP[k]` contains the LCP between `SA[k]` and `SA[k+1]`. Let's re-verify the LCP array based on the `SA`.)

Let's re-verify the LCP values based on the final `SA`:
$SA = [6, 5, 3, 1, 0, 4, 2]$
Suffixes:
`SA[0] = 6`: `$`
`SA[1] = 5`: `a$`
`SA[2] = 3`: `ana$`
`SA[3] = 1`: `anana$`
`SA[4] = 0`: `banana$`
`SA[5] = 4`: `na$`
`SA[6] = 2`: `nana$`

`LCP[0]` (between `SA[0]` and `SA[1]`): LCP(`$` , `a$`) = 0
`LCP[1]` (between `SA[1]` and `SA[2]`): LCP(`a$` , `ana$`) = 1 (`a`)
`LCP[2]` (between `SA[2]` and `SA[3]`): LCP(`ana$` , `anana$`) = 3 (`ana`)
`LCP[3]` (between `SA[3]` and `SA[4]`): LCP(`anana$` , `banana$`) = 0
`LCP[4]` (between `SA[4]` and `SA[5]`): LCP(`banana$` , `na$`) = 0
`LCP[5]` (between `SA[5]` and `SA[6]`): LCP(`na$` , `nana$`) = 2 (`na`)
`LCP[6]` is usually 0 or undefined, as it's the last element.

So, the LCP array values (for `LCP[k]` = LCP between `SA[k]` and `SA[k+1]`) are:
$\boxed{LCP = [0, 1, 3, 0, 0, 2, 0]}$ (This matches the Kasai calculation if `LCP[rank[i]]` maps to `LCP[k]` in the final array, and `LCP[N-1]` is set to 0).

**Reflection**: This example highlights the iterative nature of the doubling algorithm. The `rank` array is crucial for efficiently comparing "halves" of suffixes. Kasai's algorithm is tricky due to the `h` variable and the `rank` array lookup, but it's very efficient.
