## 1. The one-sentence answer
**The ALU is the combinational circuit inside a processor that executes arithmetic and bitwise operations on integer operands while simultaneously updating four status flags—zero, carry, overflow, and negative—that record properties of the result for subsequent conditional execution.**

An ALU receives two data words, an operation code, and a carry-in bit. It produces a result word together with four single-bit flags. These flags are not side effects; they are the mechanism that turns raw computation into decision-making. Without them a processor could only execute straight-line code.

The zero flag is set when every bit of the result is zero. The carry flag records an unsigned overflow out of the most significant bit. The overflow flag detects a signed two’s-complement overflow. The negative flag simply copies the sign bit of the result. Together they allow the control unit to implement every conditional branch in a high-level language.

> [!NOTE]
> The four flags are not independent; they are different projections of the same bit-vector arithmetic, each chosen because it answers one common question the programmer (or compiler) needs answered after every operation.

## 2. Why this matters — concrete and current
In the ARM Cortex-M4 used inside billions of microcontrollers, the ADD instruction sets the overflow flag exactly when two 32-bit signed values produce a result outside the range −2³¹…2³¹−1; the subsequent BVS instruction branches only when that flag is set, allowing safe fixed-point sensor fusion in drones without trapping into an exception handler.

Intel’s Alder Lake cores implement the same four flags on every ALU port; the carry flag produced by a 64-bit ADD directly feeds the ADC instruction that performs multi-precision arithmetic inside OpenSSL’s constant-time big-integer routines, keeping cryptographic operations side-channel resistant.

NASA’s Perseverance rover flight software, compiled for the RAD750 processor, uses the zero flag after every decrement of a timeout counter; a BNE instruction decides whether to continue the entry-descent-landing sequence or to switch to the backup timer, guaranteeing deterministic timing under radiation-induced single-event upsets.

Google’s TPU v4 matrix-multiplication units expose a “predicate” register whose bits are populated from the ALU negative and zero flags of the preceding vector compare; this enables masked execution that skips over NaN results without data-dependent branches, raising sustained utilization above 90 % on large language-model inference.

## 4. Building the idea — from intuition to formalism

### Step 1 — ALU as a black box
An ALU is a pure combinational circuit. It has no memory; every output is a Boolean function of the current inputs only.  
Example: 4-bit inputs A = 1011, B = 0011, op = ADD yields result 1110 plus four flag bits computed in the same gate delay.  
Formally,  
$$
(\text{Result}, Z, C, V, N) = \text{ALU}(A, B, \text{op}, C_{\text{in}})
$$

> [!WARNING]
> Treating the ALU as sequential will lead to incorrect pipeline diagrams; the flags are available in the same cycle as the result.

### Step 2 — Arithmetic versus bitwise results
Addition and subtraction produce a carry chain; bitwise operations (AND, OR, XOR) do not. Both classes, however, write the zero and negative flags identically.  
Example: A AND B never sets carry or overflow; it may still set zero.  
$$
Z = \bigwedge_{i=0}^{n-1} r_i, \qquad N = r_{n-1}
$$

### Step 3 — Zero flag definition
The zero flag is the NOR of all result bits.  
$$
Z = \neg(r_{n-1} \lor r_{n-2} \lor \dots \lor r_0)
$$

### Step 4 — Carry flag for unsigned arithmetic
Carry is the carry-out from the most-significant bit position during addition (or the borrow during subtraction).  
$$
C = c_n
$$
where \(c_n\) is generated by the final full adder.

### Step 5 — Overflow flag for signed arithmetic
Signed overflow occurs when the carry into the sign bit differs from the carry out of the sign bit.  
$$
V = c_n \oplus c_{n-1}
$$

### Step 6 — Negative flag
The negative flag is simply the sign bit of the result.  
$$
N = r_{n-1}
$$

### Step 7 — Flags as predicates for control flow
Every conditional branch instruction reads a Boolean function of the four flags. The mapping is fixed by the ISA:  
BEQ tests \(Z=1\), BVS tests \(V=1\), etc.

## 5. Worked examples — every step shown

**Example 1 — Simple addition setting zero**  
*Given:* 8-bit two’s-complement operands A = 0x05, B = 0xFB, op = ADD.  
*Find:* Result and all four flags.  
Step 1: 00000101 + 11111011 = 00000000 (binary).  
*Why:* Bitwise addition yields all zeros.  
Step 2: Z = 1 because every bit is zero.  
*Why:* Definition of zero flag.  
Step 3: C = 1 (carry out from MSB).  
*Why:* Unsigned overflow occurred.  
Step 4: V = 0 (cin to sign = 1, cout from sign = 1).  
*Why:* Same carry values cancel.  
Step 5: N = 0.  
**Result:** 0x00, Z=1, C=1, V=0, N=0

**Example 2 — Signed overflow**  
*Given:* A = 0x7F, B = 0x01 (both positive).  
*Find:* Flags after ADD.  
Step 1: 01111111 + 00000001 = 10000000.  
*Why:* MSB flips from 0 to 1.  
Step 2: V = 1 because cin to sign bit (0) ≠ cout (1).  
*Why:* Overflow equation.  
**Result:** 0x80, Z=0, C=0, V=1, N=1

**Example 3 — Bitwise AND**  
*Given:* A = 0xFF, B = 0x00, op = AND.  
*Find:* Flags.  
Step 1: Result = 0x00.  
*Why:* Bitwise AND clears every bit.  
Step 2: Z=1, N=0, C=0, V=0 (bitwise ops force C=V=0).  
**Result:** 0x00, Z=1, C=0, V=0, N=0

**Example 4 — Subtraction producing borrow**  
*Given:* A = 0x00, B = 0x01, op = SUB.  
*Find:* Flags (8-bit).  
Step 1: 00000000 − 00000001 produces borrow, result 0xFF.  
*Why:* Two’s-complement subtraction.  
Step 2: C=1 (borrow occurred), V=0, Z=0, N=1.  
**Result:** 0xFF, Z=0, C=1, V=0, N=1

*Reflection:* The first three examples isolate each flag; the fourth combines borrow with sign, showing that flags are orthogonal projections of the same operation.

## 6. Common traps and how to avoid them

| Trap | Why it happens | How to avoid it |
|------|----------------|-----------------|
| Confusing carry with overflow | Both flags can be set on the same addition | Remember C is unsigned, V is signed; test the correct branch mnemonic |
| Assuming bitwise ops set carry/overflow | Some assemblers leave C and V unchanged | Always consult the ISA manual for the exact instruction class |
| Forgetting that SUB sets carry on borrow | Carry flag is inverted for subtraction on some ISAs | Read the pseudocode: “C = not borrow” |
| Sign-extending before flag inspection | ALU operates on raw register width | Perform sign extension after the flag-setting instruction |
| Treating N as “negative result” on unsigned data | N merely copies the MSB regardless of interpretation | Use N only when the datum is known to be signed |
| Expecting flags after a store instruction | Stores do not pass through the ALU | Only arithmetic, logical, and compare instructions update flags |
| Overwriting flags before the branch | Another ALU op occurs between compare and branch | Insert NOPs or use flag-preserving instructions when needed |

## 7. The textbook-precise statement
An n-bit ALU computes  
$$
R = A \oplus_n B,\qquad C = c_n,\qquad V = c_n \oplus c_{n-1},\qquad Z = \bigwedge_{i=0}^{n-1} r_i,\qquad N = r_{n-1}
$$  
where \(\oplus_n\) denotes the chosen operation (addition, subtraction, bitwise, etc.) and \(c_i\) are the internal carry signals. The four flags are architecturally visible and may be read by conditional branch or predicated instructions. (Patterson & Hennessy, *Computer Organization and Design*, 5e, §4.4, “ALU Design and the Arithmetic-Logic Unit”.)

## 9. The memory technique
1. **The hook** — Picture a traffic light with four bulbs labelled Z, C, V, N; after every ALU “car” passes, the lights instantly show whether the result was zero, carried, overflowed, or negative.  
2. **What to overlearn** — The four equations for Z, C, V, N and the fact that only arithmetic and logical instructions write them.  
3. **Spaced-repetition schedule** — Review the flag equations at 1 day, 3 days, 7 days, 16 days, 35 days.  
4. **First-principles fallback** — Re-derive every flag from the definition of binary addition and the two’s-complement sign bit.
